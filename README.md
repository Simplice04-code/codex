# GraphSearch Tutor

A small, interactive lesson in Breadth-First Search (BFS) and Depth-First Search (DFS), built with HTML, CSS, and JavaScript. No external packages, fonts, or network services are required.

## Run

Use Node.js 20 or newer. No dependency installation or build step is needed.

```sh
npm start
```

The development server listens on `0.0.0.0:3000`. Set `PORT` or `HOST` to change its binding. `npm run dev` starts the same server. The HTML/CSS/JavaScript assets can also be served by a standard static web server; ES modules need HTTP rather than opening the HTML as a local file.

## Open the website in your browser

On your own computer:

1. Download and extract the complete project, keeping `styles.css` and the `js` directory alongside `index.html`.
2. Install Node.js 20 or newer if it is not already available.
3. Open a terminal in the extracted project directory and run `npm start`.
4. Leave the terminal running and open `http://localhost:3000` in your browser.

No `npm install` or build command is necessary. Do not double-click `index.html`: browsers restrict its JavaScript module imports when opened through `file://`.

When the server runs in the cloud, `localhost` refers to the cloud machine, not your computer. This cloud onboarding interface does not provide a live website preview or a forwarded browser URL. The local address above works after you run the project on your own computer. You can also deploy the HTML, CSS, and JavaScript files to a static website host without a build step.

## Troubleshoot a preview error

The message “An error occurred inside the visualization” is not generated by this application. An embedded viewer can fail independently of the website; displaying HTML alone also leaves its external CSS and JavaScript unavailable.

- Cloud restoration preserves files, but live server processes must be started again with `npm start`. Saving startup instructions does not launch the server automatically.
- Check the server terminal for startup errors. `EADDRINUSE` means the selected port is already occupied; identify the existing service or select a different `PORT`.
- In an HTTP browser session, the homepage, `styles.css`, `js/app.js`, and `js/traversal.js` must all return HTTP 200. The JavaScript responses must have a JavaScript content type.
- Check the browser console and network panel for failed module requests. Serve the whole project rather than pasting only the HTML into a visualization.
- Run `npm test` to verify the algorithms separately from any preview service.

The cloud startup instructions are saved in environment settings. Their presence does not publish the website or configure an external web host.

## Explore

- Choose **BFS** or **DFS**. Choosing an algorithm starts a fresh traversal at A.
- Click **Next Step**, or press the right arrow key, to visit one node.
- Follow the current node, visited nodes, frontier, traversal order, and plain-language explanation.
- Click **Reset** to restart the selected algorithm.

The undirected graph has edges A–B, A–C, B–D, and C–E. Neighbors are considered alphabetically. BFS visits **A → B → C → D → E** with a FIFO queue. DFS visits **A → B → D → C → E** with a LIFO stack; neighbors are pushed in reverse alphabetical order so the alphabetically first neighbor is popped first. In the displayed stack, the rightmost item is the top.

## Tests

```sh
npm test
```

Tests use Node's built-in test runner and check exact traversal orders, queue/stack contents at every step, discovery edges, independent resets, snapshot immutability, alphabetical neighbor handling, cycles, disconnected graphs, and invalid input. They execute the same traversal module used in the browser.

## Files

- `index.html`: semantic layout and the accessible SVG graph.
- `styles.css`: responsive interface, node states, and reduced-motion support.
- `js/traversal.js`: pure BFS/DFS algorithms and immutable step snapshots.
- `js/app.js`: button events and rendering of algorithm state.
- `server.js`: dependency-free local HTTP server.
- `tests/traversal.test.js`: automated traversal tests.

The interface supports keyboard navigation, an arrow-key step shortcut, screen-reader step announcements, and mobile layouts. Algorithm and application code stay separate so each is easy to understand and extend.
